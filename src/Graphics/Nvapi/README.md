# NVAPI bootstrap (bounded reconstruction)

`NvapiBootstrap.cs` is an **evidence-based C# behavioral model**, not recovered original source or a drop-in client implementation. It covers the slot-0 `nvapi.dll` acquisition/refresh path and one representative ID-dispatched NVAPI relay. `IBackend` leaves the host's indirect functions and memory accesses opaque.
Build independently with `dotnet build .\src\Graphics\Nvapi\Nvapi.Reconstruction.csproj`.

| IDA address | Observed role / reconstruction |
| --- | --- |
| `0x1F8B70` `NetSession_OpenWithRetryAndBootstrap` | `Open`: permanent-failure gate (`-2`), at most ten waits of argument `100` while close flag is set (`-1`), increment in-flight count, existing-handle lookup then fallback open; resolve/capture on new or changed handle (`-14`), otherwise `0`. Failed resolution decrements and closes the acquired handle. |
| `0x1F8950`, `0x1F89A0` | `ReadSnapshot` / capture / change test: `[handle+0x3C]` is the PE header offset; `handle+offset+0x58` is the PE optional-header `CheckSum`, and `+0x08` the COFF `TimeDateStamp`. Each slot occupies eight bytes in the snapshot globals at **VA** `0x1E44E50`. Compare checksum if nonzero, otherwise timestamp; update **both** on a detected change. |
| `0x1F8A50` | Slot-0 `ResolveFunctionTable`: look up `nvapi_QueryInterface` via the indirect call at **VA** `0x1AC4384`; query numeric interface ID `0x0150E828`, invoke the resulting function with **no arguments** (verified in disassembly); query optional hooks with IDs `0x33C7358C` and `0x593E8644`. If pre-hook exists without post-hook, clear both. |
| `0x1F8920` | `OpenNormalizePendingToOk`: maps `-14` to `0`. |
| `0x1F8E20` | `Close`: set close flag; require stored handle and resolver, reject nonzero in-flight count; resolve `0xD22BDD7E`, call with no arguments, close stored handle and clear resolver/hooks on success. Returns `-4`, `-1`, `-3` or `0` by path. |
| `0x1F8F70` | `InvokeExample`: accepts `0`/`-14` from bootstrap, invalidates its cached function on `-14`, resolves hash `0x6C2D048C` as needed, calls optional before/after hooks, invokes two-argument function, decrements in-flight count. |

**Raw-map correction:** Function addresses above are **raw file offsets**, but absolute data operands in IDA disassembly are **PE virtual addresses** (VA). See `..\..\..\docs\BinaryLayout.md`. Translate VA `0x1B33FD4` → raw `0x1732BD4` and `0x1B33FE0` → `0x1732BE0`: both contain `nvapi.dll`. VA `0x1B33FA4` → raw `0x1732BA4` contains `nvapi_QueryInterface`; the related slot-1 VA `0x1B33FBC` → `0x1732BBC` contains `nvapi_pepQueryInterface`, and slot-1 library VAs `0x1B33FEC` / `0x1B33FFC` → raw `0x1732BEC` / `0x1732BFC` contain `nvpowerapi.dll`. The C# name-address constants deliberately remain **original VAs** passed to opaque backend operations, not raw-file indexes or strings read at those numerical raw offsets. Numeric IDs passed to `nvapi_QueryInterface` are not automatically pointers: IDA's `offset loc_150E828` rendering for the immediate `0x0150E828` is misleading here.

Indirect call slots at VAs `0x1AC4370`, `0x1AC42C0`, `0x1AC430C`, `0x1AC4374`, `0x1AC4384` correspond respectively to existing lookup, fallback open, close, delay and symbol lookup **by observed call sites**, not verified host API identities. For example, the first slot's VA maps to raw `0x16C2F70`, not raw `0x1AC4370`. Slot-0 snapshot global VA `0x1E44E50` maps to `0x1A43250` but lies beyond `.data`'s raw size (uninitialized region): no initial state is inferred from raw-file bytes. The checksum/timestamp interpretation follows the PE32 header layout and was cross-checked against this executable's PE header at raw `0x170` (timestamp raw `0x178`, checksum raw `0x1C8`). What the queried interface IDs or hook functions do beyond the observed calls remains unknown.

The related slot-1 path at `0x1F8CF0` uses the same snapshot helpers and the other branch of `0x1F8A50`, but distinct flags/counters/handles and descriptors; it has no direct code xrefs in this database and is not modeled here. Representative callers: `0x1F8920`, `0x1F8F70`, `0x1F9080` (one-argument relay), `0x1F9F60` (another two-argument relay); `0x2E9A00` calls the normalize wrapper, a relay, and `0x1F8E20`.

**Caveats:** IDA's existing analyst names were checked against decompilation and relevant disassembly, but signatures of indirect calls and the backing data remain unverified. This model preserves noteworthy observed behavior rather than repairing it: normal/`-14` opens retain a count until a relay's successful invoke; the normalize wrapper and relay's missing-function (`-3`) path do not decrement it. Snapshot change is stored before resolution succeeds. No synchronization, exception handling, or behavior for unmapped memory is inferred.
